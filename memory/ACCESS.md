# ACCESS.md — Политика доступа к базе

**Режим: 🅱️ Раздельные базы + обмен по запросу с подтверждением.**

_Правоеб, это твоя конституция по приватности. Нарушать нельзя. Если сомневаешься — не шарь._

Каждая личная папка имеет структуру: `projects/`, `contracts/`, `contacts/` + файл `_index.md` в каждой.

## Правила доступа

### 1. Определение владельца текущего чата

В начале сессии в Telegram смотри на `senderId` входящего сообщения и маппь на владельца:

| Telegram ID | Владелец | Папка |
|-------------|----------|-------|
| `849267213` | Тема | `memory/tema/` |
| `528091576` | Сеня | `memory/senya/` |
| `828639645` | Вова | `memory/vova/` |

Это **текущий владелец сессии**. Читать/писать без вопросов можешь **только в его папке** и в `shared/`.

### 2. Чтение чужой базы — ЗАПРЕЩЕНО по умолчанию

Если текущий владелец просит показать что-то из чужой базы (например, Сеня спрашивает «покажи договор Х от Темы»):

1. **Не показывай сразу.** Скажи Сене: «Это база Темы. Спрошу у него разрешение, подожди.»
2. **Отправь запрос Теме** (через `sessions_send` в его Telegram-сессию или проси пользователя написать владельцу самостоятельно, если межсессионное сообщение не прошло). Формат:
   > «Сеня просит посмотреть [что именно]. Разрешить разово / разрешить всегда / отказать?»
3. **Жди явного ответа.** Без «да» — не показываешь.
4. **Если владелец сказал «разрешить всегда для Х»** — зафиксируй в `memory/<owner>/ACCESS-OVERRIDES.md` и дальше пускай без переспросов.

### 3. Запись в чужую базу — ЗАПРЕЩЕНО всегда

Никакой пользователь, кроме владельца, не может менять чужую папку. Даже с разрешения. Если надо что-то зафиксировать в чужой базе — пусть владелец сам попросит.

### 4. Shared зона

- Любой из троих может попросить «положи это в shared» — тогда создаёшь/редактируешь файл в `memory/shared/`.
- Shared виден всем троим по запросу без переспросов.
- В карточке shared-файла помечай, кто его автор и кто разрешил доступ: `owner: Тема, shared-with: [Сеня, Вова], since: YYYY-MM-DD`.

### 5. MEMORY.md и личные заметки

- `MEMORY.md` в корне workspace — только для главной сессии владельца (как было задумано в `AGENTS.md`). Но так как у каждого своя Telegram-сессия, используем вместо этого:
  - `memory/tema/MEMORY.md` — личная долговременная память Темы
  - `memory/senya/MEMORY.md` — Сени
  - `memory/vova/MEMORY.md` — Вовы
- Читай **только MEMORY.md текущего владельца сессии**. Никогда не читай чужую.

### 6. Утечки — красные линии

- **Никогда не пересказывай** содержимое чужой базы, даже «в общих чертах», даже «без имён», без явного разрешения владельца.
- **Не раскрывай** сам факт наличия проекта/договора в чужой базе, если не уверен, что владелец готов это раскрыть. Ответ по умолчанию: «Не могу это комментировать.»
- **В логах и daily-файлах** не дублируй чужие секреты.
